# wishket-radar 로드맵

상태 표기: `[ ]` 계획 · `[~]` 진행 · `[x]` 완료. 버전은 마일리지 목표치로, 실제 릴리스 시점에 조정된다.

## v0.4.x — SQLite 마이그레이션 (WAL)

state.json 단일 파일의 한계(쓰기 경합, 부분 손상, 대화 히스토리 같은 관계형 데이터 부적합)를 해소한다.

- [x] **저장 계층 추상화** — `server/src/state.rs`의 read/write를 trait 뒤로. 현재 호출부(JSON 파일)는 유지하며 교체 지점을 만든다.
- [x] **SQLite 스키마** — `state.db` 단일 파일: `seen`(공고 캐시), `applications`(파이프라인), `conversations`/`messages`(v0.5 대화, 스키마 선반영), `settings`(BYOK 등). 마이그레이션은 `rusqlite` + `user_version` pragma.
- [x] **WAL 모드 활성화** — `PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000; PRAGMA synchronous=NORMAL;`. 대시보드 3초 폴링과 쓰기가 겹쳐도 읽기 막힘 없음.
- [x] **자동 이관** — 첫 기동 시 `state.json`·`applications.yaml`·`profile.yaml`을 SQLite로 흡수하고 원본은 `*.migrated`로 보존(기존 matches.md 이관 선례 준용). 롤백 경로: 원본 파일 삭제 전까지만.
- [x] **백업 정책** — `.bak` 1세대 유지 + `VACUUM INTO` 주간 스냅샷.
- [x] **API 호환** — `/api/state` 등 기존 엔드포인트 응답 스키마 불변. webui 무수정으로 통과하는 것이 완료 기준.

수용 기준: 기존 state.json 기반 배포가 첫 기동만으로 이관되고, 테스트 전반이 SQLite 백엔드로 통과.

## v0.5.x — BYOK + webui AI 평가/대화

사용자가 자신의 LLM API 키(BYOK)를 넣으면, 채팅 세션(지금의 wishket-analyst)과 동급의 AI 평가·분석·대화를 webui에서 직접 돌린다.

- [x] **BYOK 설정 화면** — 내 정보 탭에 "AI 설정" 섹션: 공급자(Anthropic/OpenAI/호환 엔드포인트), API 키, 모델명, 온도. 키는 SQLite settings에 저장하되 OS keychain 연동은 후순위. 키는 응답 JSON에 절대 재노출하지 않음(마스킹).
- [x] **서버 AI 프록시** — `POST /api/ai/chat`: 서버가 BYOK 키로 공급자 API를 호출하는 얇은 프록시(키가 브라우저 JS에 닿지 않게). 스트리밍(SSE) 지원. 공급자 무응답·429·과다 지연 타임아웃.
- [x] **AI 평가 버튼** — 인박스 카드·상세, 파이프라인 상세에 "AI 평가" 실행. 입력은 캐시된 공고 본문+프로필, 출력은 기존 리포트 파서와 동일 포맷(`등급: X (NN점)` 5줄)으로 `reports/*.md`에 기록 — 기존 파서·배지 파이프라인 그대로 재사용.
- [x] **대화(컨텍스트) 연동** — 대화 시작 시 공고 캐시(본문·조건·매칭)를 시스템 컨텍스트로 주입. "이 공고 어때?", "제안 방향 더 구체화해줘" 같은 후속 질문이 공고 컨텍스트를 유지.
- [x] **비용·토큰 표시** — 대화별 토큰 사용량 누적 표시(공급자 응답의 usage 필드 기반). 누적·API 노출은 본 버전, 화면 표시는 v0.6 채팅 UI와 함께.

수용 기준: 키 입력 후 인박스 카드에서 AI 평가를 누르면 채팅 세션 결과와 동일 포맷으로 카드에 반영되고, 새로고침 후에도 유지.

## v0.6.x — 대화 히스토리 + 채팅 UI

- [x] **대화 화면** — 새 페이지 `#/chats`: 대화 목록(공고 연결 표시), 메시지 스트림, 입력창. 공고 상세에서 시작한 대화는 해당 공고로 태그.
- [x] **플로팅 채팅** — 전 페이지 우하단 플로팅 버튼 → 미니 모달로 즉시 질문. 모달 헤더의 확대 버튼으로 전체화면 전환(대화 화면과 같은 컴포넌트 재사용).
- [x] **히스토리 영속** — 대화·메시지는 SQLite(`conversations`, `messages`)에 저장. 목록에서 재진입하면 이전 맥락 그대로 이어가기(공급자에 전체 메시지 배열 재전송).
- [x] **삭제·정리** — 대화 단위 삭제(확인 대화상자 포함), 공고 삭제/스킵 시 연결 대화 처리 정책(유지하되 "삭제된 공고" 태그).
- [x] **모바일** — 플로팅 버튼·모달의 모바일 레이아웃(전체화면이 기본).

수용 기준: 대화를 만들고, 끄고, 다시 열어 이어서 묻고, 삭제까지 — 전부 webui 안에서 완결.

## 원칙

- 파일이 정규 소스라는 현재 철학에서 SQLite 단일 소스로 이동하되, 내보내기(markdown/json) 경로를 유지해 사람이 읽을 수 있는 형태를 보존.
- robots Crawl-delay 5초 등 수집 예절은 저장 계층과 무관하게 유지.
- BYOK 키·대화 내용은 로컬에만 — 외부 전송은 사용자가 지정한 공급자 API 호출뿐.
